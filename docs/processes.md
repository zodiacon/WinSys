# Processes and threads

Process and thread operations and what is read from a process: environment, memory, modules, windows, tokens, jobs, wait chains, zombies, .NET, symbols. Read the entry before changing it.

- **Zombies** (`Zombies.h`): `ZombieProcesses::Find` reads the system handle table, duplicates each Process handle from its owner (`PROCESS_DUP_HANDLE`; with query and synchronize access, else the handle's own) and keeps the exited ones (exit time from `GetProcessTimes`, else signaled), grouped by object address (elevated) or PID and creation time, with every handle holding each (its value, access and attributes); objects found running are skipped by address. This process's own handles are left out. The image name is the NT one (`ProcessImageFileName`, which an exited process keeps; `QueryFullProcessImageName` fails), as a DOS path.
- **Process windows** (`ProcessWindows.h`): `ProcessWindows::EnumTree` lists one window and its descendants (as Enum lists a top-level window's; none if it's gone). `ProcessWindows::Enum` lists a process's top-level windows (Z order), then its message-only ones (`FindWindowEx(HWND_MESSAGE...)`), each followed depth-first by its child windows (`WindowInfo::Parent` is the parent's index); nothing sends a message (`InternalGetWindowText`), so a hung process can't hang the caller; other desktops aren't seen. `Show` (`ShowWindowAsync`), `BringToFront` (restore, then `SetForegroundWindow`, which the caller must be allowed) and `Close` (posts `WM_CLOSE`).
- **ProcessModuleTracker** (`ProcessModuleTracker.h`): walks a process's address space (`VirtualQueryEx`, `GetMappedFileName`) for images and mapped data files, or uses ToolHelp when the process can't be opened with VM read. Each `EnumModules` rebuilds the list in address order, keeping the `ModuleInfo` objects of modules still there (key: mapped path + base) and reading the PE header only for new ones; `GetNewModules`/`GetUnloadedModules` are the differences from the previous call.
- **Token** (`Token.h`): the variable-size classes (groups, privileges, owner...) are queried into buffers of the size the token reports, as a domain account's token can have hundreds of groups. `ElevationType` isn't named `TokenElevationType` (or `TokenType`), which phnt/the SDK use for `TOKEN_INFORMATION_CLASS` values. `LsaSecurity::GetLogonSessionData` gets one logon session (only the caller's own unless elevated). `EnumLogonSessions` gets them all, leaving out those it can't read unless asked for them (`inaccessible`: then only the logon ID and `Error`, the Win32 error); `LogonTypeName` names a logon type. `EnablePrivilege` (by name or LUID; `TOKEN_ADJUST_PRIVILEGES`) and `SetIntegrityLevel` (`TOKEN_ADJUST_DEFAULT`; only lowering it needs no privilege, and lowering disables the enabled privileges) change a token.
- **Environment** (`Process::GetEnvironment`): reads the block from the process parameters, with its `EnvironmentSize`, from the 32-bit PEB for a WOW64 process (its code updates that one); names may start with `=` (the hidden per-drive current directories). Needs `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ`.
- **Process and thread operations** (`Processes.h`, `Thread.h`): besides the queries, `Process` sets the I/O priority (`SetIoPriority`; High enables `SeIncreaseBasePriorityPrivilege`), memory priority, affinity (`GetAffinity` fails with `ERROR_NOT_SUPPORTED` when the process spans processor groups) and efficiency mode (`SetEfficiencyMode`: EcoQoS plus the Idle class, as Task Manager; off restores Normal), reads its mitigation policies (`GetMitigations`, a `ProcessMitigations`), DPI awareness (`GetDpiAwareness`, from `GetDpiAwarenessContextForProcess`, telling Per-Monitor v2 and GDI scaling apart) and package full name (`GetPackageFullName`), reads the peak handle count (`GetPeakHandleCount`, `ProcessHandleCount`), gives an exited process's exit code (`GetExitCode`, nothing while it runs; STILL_ACTIVE told from a real 259 by waiting on the handle, so open it with `ProcessAccessMask::Synchronize`, which `Synchonize`, misspelled, also names), reads and sets the critical flag (`IsCritical`, `SetCritical`: `ProcessBreakOnTermination`, setting it needs SeDebugPrivilege, which it enables), empties the working set (`EmptyWorkingSet`, `PROCESS_SET_QUOTA`) and restarts a process (`Restart`: image path, command line, current directory and environment read first, then terminated, waited for up to 5 s and created again with `CreateProcess` as the caller). `AttachDebugger` starts the AeDebug key's Debugger (`GetPostmortemDebugger`) with the PID for `%ld`, leaving out the crash-only `-e %ld` and `-j 0x%p`. `InjectDll` loads a DLL into a process by its ID: a remote thread (`CreateRemoteThread`) runs `LoadLibraryW` on the path written into the target (`VirtualAllocEx`/`WriteProcessMemory`); needs `PROCESS_CREATE_THREAD`, `PROCESS_VM_OPERATION`, `PROCESS_VM_WRITE` and query access (so usually elevation for another user's or a system process), and a `createTime` guards a reused PID. A 32-bit (WOW64) target is refused (`Wow64Target`), as `LoadLibraryW`'s address differs there; `LoadLibraryFailed` means the remote `LoadLibraryW` returned null (wrong architecture, a failed `DllMain`, missing dependencies). A `DllInjectionResult` enum reports the outcome. Static helpers: `GetStructures` (the PEB, the 32-bit PEB of a WOW64 process, and each thread's TEB and stack bounds; a WOW64 thread's 32-bit TEB is two pages after its 64-bit one; stacks need `PROCESS_VM_READ`), `EnumLoadedModules` (PSAPI), `GetMainWindowTitles` (each process's frontmost visible, unowned, non-tool top-level window's title, `InternalGetWindowText`), `EnumProcessNames` (ToolHelp, which needs no access to the processes) and `GetHungProcesses` (the processes with a visible, hung top-level window, `IsHungAppWindow`, as Task Manager's "Not responding"; DWM's `Ghost` windows, which stand in for hung ones and report hung themselves, are left out). `Process::Run` (a command line through ShellExecuteEx, optionally with the `runas` verb) and `Process::RunAs` (CreateProcessWithLogonW: another user's process, with the profile loaded or the credentials for network access only) start processes; `Process::RunLimited` starts one with a Safer normal-user token made from the caller's (Administrators deny-only, most privileges removed), lowered to medium integrity (`CreateProcessAsUser`, which accepts such a filtered token of the caller's own without a privilege). On a system with more than one processor group (over 64 logical processors; `SystemInfo::GetProcessorGroups`), a process spanning groups (every process, by default, since Windows 11) is restricted by its default CPU sets (`GetDefaultCpuSetMasks`/`SetDefaultCpuSetMasks`, `GROUP_AFFINITY` per group, looked up at run time as they're Windows 11 and Server 2022 on) rather than a mask; `GetGroups` lists the groups its threads are in. `Thread` has `GetStartAddress` (`ThreadQuerySetWin32StartAddress`, `THREAD_QUERY_INFORMATION`; the process snapshots zero their start addresses for a caller that isn't elevated), `Suspend`, `Resume`, `Terminate`, `SetPriority`, `SetGroupAffinity` (which moves a thread to another group), `GetAffinity`/`SetAffinity` (within the thread's processor group; `GetAffinity` also gives the processors it may be given: its process's affinity when that's in the group, else the group's active ones) and `GetCreateTime` (to tell a thread from a later one with the same ID). `ThreadAccessMask` and `ProcessAccessMask` have the flag operators.
- **.NET** (`DotNet.h`): `DotNetInfo::GetCoreRuntimeProcesses` (the `dotnet-diagnostic-<pid>` pipes of .NET Core and later), `HasFrameworkRuntime` (the CLR's `Cor_Private_IPCBlock[_v4]_<pid>` section in the process's session; access denied counts as present; the .NET Framework 4 CLR on current Windows (Windows 11 build 29698) creates no such section there, as it moved to a private namespace, so it finds only older CLRs) and `HasRuntimeModule` (clr.dll, mscorwks.dll or coreclr.dll among the process's modules, `EnumProcessModulesEx`; query and VM read access). `QueryProcess` gives a process's runtimes, AppDomains, assemblies and modules from the runtime's rundown: a real-time ETW session (`<prefix><pid>.<n>`, so queries can overlap; orphans stopped through `EtwSession.h`) enables Microsoft-Windows-DotNETRuntimeRundown (`A669021C-...`) with the loader (0x8) and start rundown (0x40) keywords and a PID filter (`EVENT_FILTER_TYPE_PID`: only that process's runtime is told, so only it runs down); the consumer is opened first, the events parsed by ID and version in `ApplyRundownEvent` (public, apart from the session, for the tests: `Tests\DotNetTests.cpp`; a truncated payload adds nothing) (RuntimeInformationDCStart 187, AppDomainDCStart 157 (index from version 1), AssemblyDCStart 155 (BindingID from version 1), ModuleDCStart 153), done when every runtime has sent DCStartComplete (145); the session is flushed every 250 ms while waiting (else the 1 s flush timer made it 2 s; now about 0.5 s), and stopping it delivers the rest before `ProcessTrace` returns. Tested on Windows PowerShell 5.1 (.NET Framework 4: DefaultDomain and SharedDomain, NGen images) and pwsh 7 (.NET 10). Enabling needs elevation; a process without a runtime gives an empty result at the timeout.
  - `QueryCoreProcessInfo` asks a .NET Core (or later) runtime over its diagnostics pipe (`FindDiagnosticsPipe`: `dotnet-diagnostic-<pid>` on Windows, no `-<n>-socket` suffix, which is the Unix socket's), without elevation (the pipe lets in its process's user and administrators): the diagnostics IPC protocol's ProcessInfo2 (command set 0x04, ID 0x04; .NET 6 and later), else ProcessInfo (0x00) when the runtime answers with 0x80131384 (unknown command). A request is the 20-byte header (`DOTNET_IPC_V1` and its NUL, the message's size, the command set and ID, reserved); the answer's command set is 0xFF, its ID 0x00 for OK (else an HRESULT follows); one command per connection, overlapped reads and writes given up at the timeout (a suspended process doesn't answer). `ParseProcessInfo` (apart, for the tests) reads the payload: the PID, the runtime's cookie (a GUID), then strings (a count of characters with the NUL, the characters): command line, OS, architecture, and for ProcessInfo2 the entry assembly and the CLR's product version ("10.0.14"); cut short, nothing. Tested on pwsh 7.
  - `DotNetGcMonitor` follows a process's garbage collections: a real-time ETW session (`<prefix><pid>.<n>`) on Microsoft-Windows-DotNETRuntime (`E13C0D23-...`), the GC keyword (0x1) at the informational level and a PID filter, the consumer on a thread of its own. `ApplyGcEvent` (static, for the tests) folds in GCStart (1: the collections by generation, the last depth and reason), GCHeapStats (4: the generations' sizes, the large object heap's (generation 3), the pinned objects, the GC handles, and from version 2 the pinned object heap's), GCSuspendEEBegin (9) and GCRestartEEEnd (3), whose difference is a pause (the session's QPC time stamps come to the consumer as 100 ns system time); `GetStats` copies the stats under an SRW lock, `Flush` delivers the buffers at once (the session flushes every second), `Stop` (and the destructor) stops the session, which delivers the rest, and joins the thread. Needs elevation. Tested on pwsh 7 forcing a collection (`[GC]::Collect()`: a generation 2 one, about 2 ms paused).
- **Symbols** (`SymbolHandler.h`): DbgHelp isn't thread-safe, so the caller must make every call (handlers and `MiniDump`) from one thread. `SetOptions` once; `ForProcess` (by ID and creation time, so a reused ID fails) and `ForKernel` (the loaded drivers from `SystemModuleInformation`; their bases need elevation; a fixed pseudo-handle, so one at a time). `GetSymbol` refreshes the module list (at most every 2 s) when an address is in none. `CaptureStack` suspends the thread only to copy its context and stack (from the stack pointer to `StackBase`, at most 1 MB; a WOW64 thread's 32-bit ones too) and walks the copy, so no symbol download happens with the thread suspended. `GetModuleSymbols` tells where a module's symbols came from (PDB with its path, exports only, none, or not loaded yet: with deferred loads, only `GetSymbol` loads them). `MiniDump::Write` writes a mini or full dump. Which `dbghelp.dll` is used is the caller's choice (load it first; the system's can't download symbols).
- **Jobs** (`Job.h`): no API opens a process's job, so `JobInfo::FindProcessJobs` scans the system handle table for Job handles, duplicates them from their owners (`PROCESS_DUP_HANDLE`, so mostly only when elevated), keeps those `IsProcessInJob` accepts (told apart with `NtCompareObjects`) and orders them innermost first by active processes (nothing documented gives a job's parent; `ordered` says whether the counts told them apart). Also a job's name, active processes and process IDs. `GetSiloInfo` describes a job that's a silo (`SiloInfo`; nothing, with the last error set, for a plain job): JobObjectSiloBasicInformation (36: its ID, parent silo, processes, whether it's a server silo), JobObjectSiloRootDirectory (37: the root of its object namespace, a `UNICODE_STRING` in the buffer) and, for a server silo (a Windows container), JobObjectServerSiloBasicInformation (38: the service session, the state (`ServerSiloStateName`: Initing, Started, Shutting Down, Terminating, Terminated), exit status, and the container's and host's builds). A silo is made from a job with `JobObjectCreateSilo` (35), which needs `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` set first (STATUS_INVALID_PARAMETER otherwise); the tests do that for an app silo.
- **Wait chains** (`WaitChain.h`): `WaitChainTraversal::GetThreadWaitChain` (WCT, synchronous, with ole32's COM callbacks registered once). WCT's thread `WaitTime` is the clock tick the wait began on, not a duration; it's converted to the milliseconds since.
- **Process memory** (`ProcessMemory.h`): `FindStrings` (Sysinternals Strings' runs: printable ASCII and tab as single bytes, plus Latin-1 0xA0-0xFF as UTF-16 units at even addresses, which as single bytes were mostly binary noise; at least `MinLength`, the text cut at `MaxText`, at most `MaxResults`; the same readable regions as `Find`, merged when adjacent so a run may cross them, read in 1 MB chunks; a `StringScanProgress` told after each chunk can stop it; the results in address order; about 2 s for 320 MB committed), `Find` (a byte pattern in an address range, through the committed regions that can be read without side effects, in 1 MB chunks that overlap by the pattern's length; adjacent readable regions searched as one range, so a match may cross them; optionally ignoring ASCII case, with `wide` by UTF-16 units, folding only units whose high byte is zero), `Read` (what can be read; unreadable pages as zeros, page by page when the whole read fails), `GetMappedFileName` (the file mapped at an address, from `NtQueryVirtualMemory`'s `MemoryMappedFilenameInformation` with a buffer that grows, as psapi's `GetMappedFileName` cuts a name to the buffer it's given; `ProcessModuleTracker` uses it too), `Write` (`WriteProcessMemory`, which makes a read-only or executable page writable for the write when the handle has `PROCESS_VM_OPERATION`) and `MaxAddress`. `Find` avoids `<functional>`'s searchers (see the exception note above).
- **Heaps** (`Heaps.h`): `ProcessHeaps::Query` gives a process's heaps (`HeapInfo`: address, flags with the class, NT or segment heap, the default one, committed, reserved, allocated, segments) from `RtlQueryProcessDebugInformation` with `RTL_QUERY_PROCESS_HEAP_SUMMARY | RTL_QUERY_PROCESS_HEAP_SEGMENTS | RTL_QUERY_PROCESS_NONINVASIVE`: read from outside the process, without the remote thread the invasive query creates (about a millisecond for explorer's 51 heaps). The buffer is an `RTL_PROCESS_HEAPS` whose entries are `RTL_HEAP_INFORMATION_V2` (96 bytes, a heap tag at the end) after Windows 11 build 22000 and V1 (88) before (`UsesV2`); with the segments flag each heap's entries are its segments (`RTL_HEAP_SEGMENT`, `Size` reserved, `CommittedSize`), whose sizes add up to the reserve (blocks too large for a segment aren't among them: explorer's default heap 451,452,928 bytes against 451,330,048 from `HeapExtendedInformation`, which needs a full-access handle and which Defender flagged in a probe, so it isn't used). The segment heap reports no flags, entry overhead or allocated bytes (0); the kind is told by the signature 16 bytes into the heap (0xFFEEFFEE NT, 0xDDEEDDEE segment; `PROCESS_VM_READ`), else guessed from a zero overhead, and the default heap is `PEB.ProcessHeap`. `Parse` (the buffer, apart from the query, for the tests: `Tests\HeapTests.cpp`), `ClassText` (`HEAP_CLASS_*`: Private, CSR port...) and `FlagsText`. The caller's own processes need no elevation, other users' do, protected ones fail with access denied; a 32-bit (WOW64) process fails with `ERROR_INVALID_PARAMETER` (the non-invasive query reads 64-bit heaps only; the invasive one would inject a thread). If the default buffer is too small (`STATUS_NO_MEMORY`) the query runs again with one of up to 64 MB.
