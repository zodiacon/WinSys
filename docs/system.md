# System

System-wide queries and operations: memory, processors, disks, power, firmware, services, kernel modules, sessions, startup locations and other system information. Read the entry before changing it.

- **Power** (`Power.h`): `Lock` (`LockWorkStation`), `LogOff` (`ExitWindowsEx`), `Sleep` and `Hibernate` (`SetSuspendState`), `Restart`, `Shutdown` and `RestartToBootOptions` (`InitiateShutdown`, `SHUTDOWN_RESTART_BOOTOPTIONS`), with a planned \"other\" reason, SeShutdownPrivilege enabled; `RestartToFirmware` sets `EFI_OS_INDICATIONS_BOOT_TO_FW_UI` in the global `OsIndications` variable (NV|BS|RT, keeping its other bits; SeSystemEnvironmentPrivilege, so elevation) and restarts, as `shutdown /r /fw`. `CanSleep` (S1-S3), `CanHibernate` (S4 and a hibernation file, `GetPwrCapabilities`) and `CanRestartToFirmware` (UEFI, and `OsIndicationsSupported` has the bit; unreadable without elevation). `powrprof.lib` by a pragma.
- **Pipes and mailslots** (`Pipes.h`): `Pipes::EnumPipes`/`EnumMailslots` list `\Device\NamedPipe\` and `\Device\Mailslot\` with `NtQueryDirectoryFile` (`FileDirectoryInformation`), the root opened with `FILE_LIST_DIRECTORY` but without `FILE_DIRECTORY_FILE`, which the mailslot file system's root fails (`STATUS_OBJECT_NAME_INVALID`). A pipe's end of file is its current instances and its allocation size the most allowed (0xFFFFFFFF for unlimited, made -1); mailslot names may have backslashes (nested names come flat); only mailslots have a creation time (the named pipe file system reports no times at all). Only the roots are opened: opening a pipe would connect to it as a client. A consumer with exceptions on should avoid range `insert` into a `std::vector` of these types: under LTCG it warned C4530 (the exception note above).
- **Network shares** (`NetworkShares.h`): `NetworkShares::Enum` tries `NetShareEnum` at levels 502 (path, uses, the share's security descriptor, read into `Permissions`: allow and deny ACEs with their trustees' names), 2 and 1 (name, type, comment), falling to the next on access denied (documented for non-administrators at 502 and 2; current Windows allows them locally), and says which it got; every share's `SHI1005_FLAGS_*` from `NetShareGetInfo` level 1005. `TypeName`, `RightsName` (the share permissions' Full Control, Change and Read masks) and `CachingName`. `netapi32.lib` by a pragma.
- **Page files** (`PageFiles.h`): `PageFiles::Enum` (`SystemInfo::GetPageFileInformationEx`, else the plain query without the minimum and maximum; sizes in bytes; `\??\` names as DOS paths) and `GetConfiguration` (the Memory Management key: `PagingFiles` lines, `<path> [<initial MB> <maximum MB>]`, `?:\pagefile.sys` meaning managed automatically and sizes of 0 a system-managed file, `ExistingPageFiles`, `ClearPageFileAtShutdown`, `DisablePagingExecutive`). No elevation needed.
- **Memory lists** (`MemoryLists.h`): `MemoryLists::Read` (`SystemMemoryListInformation`: zeroed, free, modified with its no-write and page-file parts, bad, the standby list per priority, in bytes, and the pages repurposed from each priority since boot, a count) and `Execute` (`NtSetSystemInformation` with a `SYSTEM_MEMORY_LIST_COMMAND`: empty working sets, flush the modified list, purge the standby list or its priority 0 part). Both enable SeProfileSingleProcessPrivilege, so they need elevation (`ERROR_PRIVILEGE_NOT_HELD` otherwise); `SystemInfo::GetMemoryListInformation` is the raw query.
- **Physical memory** (`PhysicalMemory.h`): `PhysicalMemory::GetRanges` (`SystemSuperfetchInformation` with `SuperfetchMemoryRangesQuery`, a `PF_PHYSICAL_MEMORY_RANGE_INFO_V2`, else V1; the buffer grows on `STATUS_BUFFER_TOO_SMALL`) and `PageUseCounts::Read`, RAMMap's Use Counts: every page of the ranges through `SuperfetchPfnQuery` (a `PF_PFN_PRIO_REQUEST` with the page frame numbers filled in, 64K pages a call), counted by `MMPFN_IDENTITY`'s use and list; zeroed, free and bad pages go to `Unused`, as their use is stale. All from phnt (`ntpfapi.h`, `ntmmapi.h`), the `SUPERFETCH_INFORMATION` version 45 and its magic. SeProfileSingleProcessPrivilege is enabled; a non-elevated caller gets `ERROR_ACCESS_DENIED`. The time is the kernel's: about 160 ms per 4 GB (5-6 s for 128 GB), and small batches are slower (128 pages: 7-8 s), so callers run it on a thread of their own; `cancel` is checked between batches. It isn't a snapshot: pages move meanwhile. Measured on Windows 11 (build 29695): use 12 occurs (unnamed in phnt, about 50 MB, mostly active): `PageUse::Hyperspace`, from the kernel's disassembly (`MiIdentifyPfn` calls `MiIdentifyUserPage`, which sets 12 for a page at an address in the hyperspace range, `MiState+0x1FE0` to `+0x2128` on that build, or a page table that `MiHyperPage` says maps it, recording the owning process), so undocumented and may differ in other builds, and list 5 (Bad) holds about 95 MB with raw identity `0x50` and nothing else, while `SystemMemoryListInformation`'s `BadPageCount` is 0, so those pages are something the PFN query reports as bad rather than bad pages (unverified what).
- **Cores** (`SystemInfo::GetLogicalProcessorCores`): each logical processor's physical core and that core's efficiency class (`RelationProcessorCore`; higher is faster, all equal unless the processor is hybrid), indexed group by group by the processor's place among its group's active ones, as the per-processor queries number them.
- **Processor frequency** (`ProcessorFrequency.h`): `ProcessorFrequency` reads each logical processor's actual frequency as Task Manager's Speed, through PDH with the counters' English names (`PdhAddEnglishCounter`): `\Processor Information(*)\Processor Frequency` (rated) times `% Processor Performance` (over 100 while boosting; a rate, so `Open` collects once). Instances are `<group>,<number>`, mapped to indices group by group (`GetActiveProcessorCount`), as `SystemInfo`'s per-processor queries number them. `CallNtPowerInformation`'s `CurrentMhz` stays at the rated frequency, so it isn't used. `pdh.lib` by a pragma.
- **Disk** (`Disk.h`): `DiskInfo::GetVolumes` (fixed and removable drives with a letter; no media and `subst` drives skipped) and `DiskTracker`, which computes read/write rates, active time and response time between `Update()` calls. The counters come from `IOCTL_DISK_PERFORMANCE` on `\\.\X:`, opened with no access, so no elevation is needed. The handle is opened for each query, so removable drives can still be ejected. `winioctl.h` is already included through `vds.h` in the pch; including it again redefines its GUIDs (`INITGUID` is on).
- **Firmware and TPM** (`Firmware.h`), read-only: `Firmware::GetType` (`GetFirmwareType`), `EnumVariables` (`NtEnumerateSystemEnvironmentValuesEx` with `SystemEnvironmentValueInformation`, enabling SeSystemEnvironmentPrivilege, which only an elevated token has; the buffer grows if variables are added between the calls) and `GetBootConfiguration` (from those variables: `BootOrder`, `BootCurrent`, `BootNext`, `Timeout`, `SecureBoot`, `SetupMode`, and each `Boot####` load option's attributes, description and the device path's file path nodes). `Tpm::GetInfo`: TBS's device info, and for TPM 2.0 one `TPM2_GetCapability` of the fixed properties (`TPM_PT_FAMILY_INDICATOR` on: family, level, revision, date, manufacturer, vendor strings, firmware version), big-endian, through a TBS context (`tbs.lib` by a pragma). Nothing is written to the firmware or the TPM.
- **Autoruns** (`Autoruns.h`): `Autoruns::Enum`, Sysinternals Autoruns' main locations, read directly: the Run and RunOnce keys (HKLM, HKCU, WOW6432Node, the Explorer policies' Run), the startup folders (from `%APPDATA%` and `%ProgramData%`, as the known folder IDs aren't defined here; shortcuts resolved with `IShellLinkW`), Active Setup's StubPath (placeholders that name no file left out), every scheduled task in every folder (`TASK_ENUM_HIDDEN`; actions, COM handlers by InprocServer32, trigger kinds counted, principal, last and next run as UTC FILETIMEs from local `DATE`s, `$(@...)` strings through `SHLoadIndirectString`), the Services key's subkeys with Start 0-2 (drivers by `KernelModules::DriverImagePath`, a shared host's service by its ServiceDll), Winlogon's Userinit (a comma list) and Shell, AppInit_DLLs, Session Manager's BootExecute ("autocheck" dropped), the LSA's packages (System32 DLLs) and IFEO Debugger and SilentProcessExit MonitorProcess values. The caller initializes COM. `ResolveImage` turns a command line into the file it runs: environment variables, quotes, an unquoted path with spaces tried word by word, `\SystemRoot\`, relative System32 paths, the search path (.exe), rundll32's DLL after its switches. `SetEnabled` writes Task Manager's StartupApproved value (2 enabled; 3 with the time, disabled; Run32 for WOW6432Node, StartupFolder for the folders) or a task's Enabled; `Delete` removes a Run or hijack value, a startup file or a task (and the StartupApproved value). Failures set the last error. `taskschd.lib`, `shlwapi.lib` by pragmas.
- **System details** (`SystemDetails.h`), decoded for a System Information page, in plain types (no phnt in the header), no elevation needed: `GetOs` (RtlGetVersion, the CurrentVersion key's names with UBR, the ProductName's "Windows 10" made 11 from build 22000, InstallTime or InstallDate, boot time and fast startup from `SystemTimeOfDayInformation`/`SystemBootEnvironmentInformation`, names, `NetGetJoinInformation`, time zone, locales), `GetSecurity` (Secure Boot, the code integrity options, isolated user mode, LsaIso.exe running for Credential Guard, the kernel debugger, KVA shadow, speculation control, shadow stacks, DMA guard, measured launch, and the `RunAsPPL`, UAC and Smart App Control registry values; each optional when its query fails), `GetProcessor` (CPUID on x86/x64 only, `IsProcessorFeaturePresent`, `GetLogicalProcessorAndGroupInformation`'s topology and caches, P/E cores by efficiency class, the CentralProcessor key's `~MHz` and `Update Revision`, whose half that's zero is dropped: Intel keeps the revision in the upper half, AMD in the lower) and `GetHardware` (`GetSystemFirmwareTable('RSMB')`: types 0, 1, 2, 16 and 17, lengths checked before every field, OEM placeholder strings such as "Default string" made empty). `netapi32.lib` by a pragma.
- **Logon task** (`LogonTask.h`): `LogonTask::Register`, `Delete` and `GetAction`, a Task Scheduler task in the root folder (`ITaskService`, `wil::com_ptr_nothrow`; the caller initializes COM) that starts a program at the current user's logon (`DOMAIN\user` from `GetUserNameEx`, as the principal and the trigger), with an interactive token, optionally at the highest run level (registering one needs elevation), no time limit, also on batteries, at priority 4 (the default 7 would start it below normal with low I/O and memory priority). `RegisterOnDemand` is the same task without a trigger and with parallel instances (the default, IgnoreNew, would drop a run while one is going), for `Run` (`IRegisteredTask::Run`), which its user may call unelevated: an elevated start without a UAC prompt. Failures set the last error (the Win32 error inside an HRESULT, else the HRESULT). `taskschd.lib`, `secur32.lib` by pragmas.
- **Zip** (`ZipArchive.h`): `ZipArchive::Extract` runs System32's `tar.exe` (bsdtar, which reads zip files; Windows 10 1803 on) hidden and waits for it, rather than the shell's Compressed Folders (progress windows) or a library.
- **Pool tags** (`PoolTags.h`): `PoolTagDescriptions` parses `pooltag.txt` (`<tag> - <binary> - <description>`; comments start with `//` or `rem`; the tag is the first four characters, spaces included, as the kernel pads short tags with spaces; the first line for a tag wins) from a file (`Load`) or text (`Parse`), and `FindFile` finds the Debugging Tools' copy under `%ProgramFiles(x86)%\Windows Kits\10\Debuggers\{x64,x86}\triage` (an environment variable rather than `FOLDERID_ProgramFilesX86`, which the library's `INITGUID` setup doesn't define). `TagText` shows a tag's four characters. The counters are `SystemInfo::GetPoolTagInformation`.
- **Sessions** (`Sessions.h`): `SessionManager::EnumSessions` (WTS, without listeners), `GetDetails` (logon/connect times, client name), `Disconnect`, `Logoff`. The detail queries raise first-chance RPC exceptions (0x6BA) that WTS handles, so pollers should enumerate without details and get them only on change. `wtsapi32.lib` is linked by a `#pragma comment` in `Sessions.cpp`.
- **GPU** (`Gpu.h`): D3DKMT. `GpuInfo::GetAdapters` (`D3DKMTEnumAdapters2`; software and non-rendering adapters left out; names from DXGI; engines from `KMTQAITYPE_NODEMETADATA`, grouped by name; aperture segments count as shared memory). `GpuTracker` samples the nodes' running times (treated as 100 ns units) and the segments' resident bytes; an engine's utilization is its busiest node's, an adapter's its busiest engine's. NPUs are a second adapter list (`GpuAdapterKind::Npu`, for `GetAdapters`, `GpuTracker` and `QueryProcess`): the compute-only adapters DXCore marks with `DXCORE_HARDWARE_TYPE_ATTRIBUTE_NPU` (dxcore.dll loaded at run time; the GUID copied rather than linked), named by DXCore's driver description; the GPU list leaves them out. `GpuInfo::QueryProcess` gives a process's usage between calls (with `details`, also per adapter: each engine's percentage, its busiest node's, and the dedicated and shared memory; no more queries than without) (`GpuProcessState` holds the previous values); it needs `PROCESS_QUERY_INFORMATION` (a limited handle fails with `STATUS_INVALID_PARAMETER`). `dxgi.lib` and `gdi32.lib` are linked by `#pragma comment`.
- **Kernel modules** (`KernelModules.h`): `KernelModules::Enum` (built on `SystemInfo::GetKernelModuleInformation`) gives the kernel's loaded modules with Win32 paths (`ToWin32Path`: `\SystemRoot\`, `\??\`, `\Device\...` and rootless `\Windows\...` paths) and wide names (the kernel's are ANSI); the bases are zero unless elevated. With `SystemModuleInformationEx` (`GetKernelModuleInformationEx`) each module also has its image's link time, checksum and preferred base; if that query fails, the plain one is used without them. `SymbolHandler::ForKernel` uses it. `DriverImagePath` gives a driver service's image (its ImagePath, possibly relative to the system root, or the default `System32\drivers\<name>.sys`) as such a Win32 path, to match a service with its loaded module.
- **Files** (`FileSignature.h`, `FileVersion.h`): `FileSignature::Verify` (Authenticode: the embedded signature, else the system catalog that lists the file's hash; no revocation checks, so nothing goes to the network; safe on any thread, but the catalog lookups may use COM) and `FileVersion::Read` (the version resource's description, company and version, in its first listed language).
- **Service configuration** (`Service.h`): `ChangeConfig` (a `ServiceConfigChange` of optional start type, error control, binary path, display name, account and password: `ChangeServiceConfig`), `SetDescription`, `SetDelayedAutoStart`, `GetFailureActions` and `SetFailureActions` (`ServiceFailureActions`: reset period, reboot message, command, the actions with their delays, and `OnNonCrashFailures`, the failure actions flag). They need `SERVICE_CHANGE_CONFIG`; a Restart action also needs `SERVICE_START` on the handle, and a Reboot action SeShutdownPrivilege, which `SetFailureActions` enables for the call. `TokenAccessMask` has the flag operators. `GetDependents` (`EnumDependentServices`, `SERVICE_ENUMERATE_DEPENDENTS`) lists every service depending on one, directly or not; the active ones come in the order to stop them. `GetSecurity`/`SetSecurity` read and write the service's security descriptor (`QueryServiceObjectSecurity`, `SetServiceObjectSecurity`; `READ_CONTROL`, `WRITE_DAC`, `WRITE_OWNER`, which `ServiceAccessMask` has), and `GetGenericMapping` gives the SCM's generic mapping; `AccessMaskDecoder` knows a "Service" type for its rights. `GetTriggerDetails` copies the triggers out with their subtypes and data items (`GetTriggers` gives only the types, actions and data item counts, its pointers null, as the buffer they would point into is freed), and `GetEventProviderName` names an ETW provider from its `WINEVT\Publishers` key. `ServiceManager::Install` builds the dependencies' list from `;`-separated names of any length and keeps `CreateService`'s error for the caller (closing the SCM handle may change it).
- **Other**: `Sid::AppContainerMoniker` (`AppContainerLookupMoniker`, in kernelbase but no SDK header, resolved at run time); `ServiceManager::GetServiceDll` (the `ServiceDll` value of a service's key or its `Parameters` subkey; a user service instance's from its template's key).
- **VDS** (`VirtualDiskService`, `VdsProvider`, `VdsVolume`) is COM-based and uses `wil::com_ptr`. The caller must initialize COM.
- **Power requests** (`PowerRequests.h`): `PowerRequests::Enum` (`NtPowerInformation` level 45, GetPowerRequestList, undocumented, called directly: powrprof's `CallNtPowerInformation` rejects the level with `STATUS_INVALID_PARAMETER`; the buffer grows on `STATUS_BUFFER_TOO_SMALL`): a count, then offsets from the list's start to entries laid out as phnt's POWER_REQUEST V4 (a mask, six counts: Display, System, Away mode, Execution, Performance boost, Active lock screen; then a DIAGNOSTIC_BUFFER at +0x20), defined in the .cpp as the library's PHNT_VERSION leaves V4 out. Verified on build 29698: the diagnostic buffer's strings (a process's NT image path, made a DOS path with `DosNames`; a driver's device description and instance path) are at offsets from the buffer's start, a reason's (COUNTED_REASON_CONTEXT_RELATIVE: a simple string, or a resource DLL and string ID with substitution strings stored one after another) from the reason's; a detailed reason is loaded with `LoadStringW` from the DLL as a data file (System32 for a bare name) and formatted with `FormatMessage` (`%1`...). Entries with all counts zero are created but not set (`activeOnly` drops them; powercfg shows none of them). A service requester's name comes from its tag through advapi32's undocumented `I_QueryTagInformation` (level 1, name from tag; advapi32 loaded explicitly, as a caller may not have it). `EnumWakeTimers` (level 50): a WAKE_TIMER_INFO list linked by `OffsetToNext` whose `DueTime` is the time left (100 ns), made a UTC FILETIME; an empty list is one empty entry. `GetTimerResolution` (`NtQueryTimerResolution`: coarsest, finest, current). The buffers' parsing is apart from the queries, `ParseRequestList` and `ParseWakeTimers` (bad counts and offsets skipped, nothing read past the buffer), for the tests (`Tests\PowerRequestTests.cpp`, buffers built in these layouts). Elevation needed, as for powercfg. Checked entry for entry against `powercfg /requests` and `/waketimers`, with a test request (`PowerCreateRequest`) and a test wake timer (`SetWaitableTimerEx` with a reason).
- **Devices** (`Devices.h`): `Devices::Enum`, the device tree through CfgMgr32 (`cfgmgr32.lib` by a pragma): from `CM_Locate_DevNode`'s root, depth-first (children by recursion, siblings in a loop; 14 levels here), each device's properties from `CM_Get_DevNode_Property` with the `DEVPKEY_Device_*` keys (friendly name or description, class and class GUID, manufacturer, service, driver version, date, provider, INF, location, PDO name, enumerator) and `CM_Get_DevNode_Status` (DN_* flags; the problem code only with `DN_HAS_PROBLEM`); `HasProblem` excludes `CM_PROB_DISABLED`, which `IsDisabled` is; `IsHidden` is `DN_NO_SHOW_IN_DM`. The class descriptions Device Manager shows ("Network adapters") come from `CM_Get_Class_Property` with `DEVPKEY_NAME`, once per class GUID (`ClassName`, else the class's own name). With `disconnected`, the IDs from `CM_Get_Device_ID_List` (`CM_GETIDLIST_FILTER_NONE`) not in the tree are located as phantoms (`CM_LOCATE_DEVNODE_PHANTOM`) and added with `Present` false and no parent. `ProblemText` words the CM_PROB_* codes with the number. `ScanForChanges` is asynchronous (`CM_REENUMERATE_ASYNCHRONOUS`): the synchronous call took 3.3 s here. `SetEnabled` (SetupAPI: `SetupDiOpenDeviceInfo`, `SP_PROPCHANGE_PARAMS` with `DICS_ENABLE`/`DICS_DISABLE` and `DICS_FLAG_GLOBAL`, `SetupDiCallClassInstaller(DIF_PROPERTYCHANGE)`; `DeviceChangeResult::RestartNeeded` when the install params get `DI_NEEDRESTART` or `DI_NEEDREBOOT`) and `ScanForChanges` (`CM_Reenumerate_DevNode` on the root) change things, and need elevation; `setupapi.lib` by a pragma. No elevation; here 294 present devices and 201 disconnected in about half a second. `GetResources` reads the device's allocated logical configuration (`CM_Get_First_Log_Conf` with `ALLOC_LOG_CONF`, else `BOOT_LOG_CONF`; none for most software devices) and each resource descriptor (`CM_Get_Next_Res_Des` with `ResType_All`, `CM_Get_Res_Des_Data`): memory (`MEM_DES`), large memory (`MEM_LARGE_DES`: a GPU's 64-bit BARs), I/O, interrupts (`IRQ_DES`, the 64-bit one on x64; a message-signaled interrupt's number is negative as an `int32_t`, as Device Manager shows it), DMA and bus numbers, with their flags; others (device-private, class-specific) are skipped. `GetDriverStack` lists the drivers loaded for a device from the top: the class's upper filters (`CM_Get_Class_Property` with `DEVPKEY_DeviceClass_UpperFilters`), the device's (`DEVPKEY_Device_UpperFilters`), the function driver (`DEVPKEY_Device_Service`), the class's and the device's lower filters, and the bus driver (the parent's service); each with its image from the service key's `ImagePath` through `KernelModules::DriverImagePath` (empty if there's no such service). `GetClassIconPath` is `DEVPKEY_DeviceClass_IconPath`'s first entry with the environment variables expanded ("C:\WINDOWS\System32\setupapi.dll,-5"), for loading a class's icon at any size; `ResourceTypeName` and `DriverRoleName` name the enums. A live test (`Devices_LiveResourcesAndDrivers`) checks a started PCI device's resources and stack (the bus driver last, the roles in order).
- **Event logs** (`EventLog.h`): `EventLog::Query` (`EvtQuery` on a channel path in reverse, an XPath of the levels, with level 0 counted as information, and `timediff(@SystemTime)` for the span; `EvtNext` in batches of 64) and `EventLogWatcher` (`EvtSubscribe` with `EvtSubscribeToFutureEvents` per channel, with the levels' query or one of the caller's per channel (`Start` with channel and XPath pairs: the Alerts' rules); the callback, the .cpp's, renders each event and gives it to an `EventLogSink`, a non-owning interface; its state, the sink, the render context and the publisher cache, is `EventLogWatcher::State`, public only for the callback; closing a subscription waits for its callback). Each event: `EvtRender` with `EvtRenderContextSystem` (provider, channel, computer, event ID, level, time created, record ID, process and thread IDs, keywords, each read only with the type it should have) and the message from `EvtFormatMessage` (`EvtFormatMessageEvent`, trailing line breaks dropped) with the provider's metadata (`EvtOpenPublisherMetadata`, once per provider, failures remembered, under an SRW lock as callbacks can run at once). The Security log's events are level 0 and told by their keywords (`EventLogEntry::AuditFailureKeyword` 0x10000000000000, `AuditSuccessKeyword` 0x20000000000000; `IsAuditFailure`, `IsAuditSuccess`, `EventLog::LevelText`): the levels' XPath adds `band(Keywords,...)` for the failures when the highest level is warnings (level 0, with information, takes the successes too), so the same query does for every log. `Exists` (`EvtOpenLog`; access denied counts as there, `ERROR_EVT_CHANNEL_NOT_FOUND` doesn't). `GetXml` finds an event by its record ID (`*[System[EventRecordID=N]]`) and renders its XML (`EvtRender` with `EvtRenderEventXml`, one line). `ParseData` takes an event's data fields from that XML (`EventDataItem`: name and value): `<EventData>`'s `<Data Name='x'>` items (an empty name for the classic logs' unnamed ones; `<Binary>` skipped), else the elements under `<UserData>`'s first child (1102's `LogFileCleared`); either quote, the entities and character references decoded, a nested element's tags dropped from a value; broken XML gives what was read before it, never a crash. A small parser of its own (the rendered XML's layout is fixed), as no XML library is linked; tested on the layouts Windows renders, and live (`EventLog_LiveEventData`). `GetData` is `GetXml` then `ParseData`; finding an event again costs about 13 ms in a large Security log (2 ms in System), so for many events the data is read with them instead: `Query`'s `EventDataRead` (`All`, or `NoMessage` for the events whose publisher has no message) and `EventLogWatcher::Start`'s `data` render each event's XML on the handle at hand and parse it into `EventLogEntry::Data` (about 15 µs an event: 5,000 Security events in 1.37 s against 1.31 s without; a live test checks the fields match `GetData`'s). `Query`'s order is the log's in reverse (by record ID), which is by time only while the clock never went back: on a new VM that syncs its clock after booting (the CI runners) later records have earlier times, which a test asserting time order caught. `wevtapi.lib` by a pragma. System and Application need no elevation; Security does (the query fails without it); about 30 ms for a day's errors and warnings each here. Verified live with Windows PowerShell's own log (starting powershell.exe writes events 400, 403 and 600), as the other logs can go minutes without an event.
