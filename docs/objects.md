# Handles and objects

Handles, the objects behind them, the object namespace, access masks and window stations. Read the entry before changing it.

- **Object namespace** (`ObjectNamespace.h`): `EnumDirectory` (`NtOpenDirectoryObject`, `NtQueryDirectoryObject` in 64 KB batches until `STATUS_NO_MORE_ENTRIES`), `GetSymbolicLink` (the target, growing the buffer when the link says so, and the creation time from `ObjectBasicInformation`), `Open` (a named object through its type's own open function: Directory, SymbolicLink, Event, Mutant, Semaphore, Section, Timer, IoCompletion, Job, Key, Session, EventPair; not devices or files, as opening a device can have effects; `ERROR_NOT_SUPPORTED` for other types), `GetHandleCount` (minus the handle opened to read it) and `Describe` (a handle of this process as the handle table lists it: access, attributes and type index from `NtQueryObject`, for `ObjectInspector`). Paths are case-insensitive (`OBJ_CASE_INSENSITIVE`).
- **Handles** (`Handles.h`): `HandleEnumerator` lists a process's handles (or every process's, `EnumSystemHandles`) from the process (`ProcessHandleInformation`: cheap, no object addresses) or from the system handle table (`SystemExtendedHandleInformation`: object addresses when elevated, ~33 ms for ~360,000 handles; the buffer is kept). Since Windows 11 24H2 the table has the addresses only while the caller has SeDebugPrivilege enabled (null otherwise, elevated or not); the library doesn't enable it, the app does (`SecurityHelper::EnablePrivilege(SE_DEBUG_NAME, true)` at startup). `ObjectTypes::GetName` (cached from `ObjectTypesInformation`); `ObjectTypes::Enum` (every type's counts, peaks, access mask, generic mapping, pool type and charges, read fresh: `ObjectTypeInfo`) and `PoolTypeName`. `ObjectNameQuery` queries object names on a worker thread with a timeout, because a name query on a file opened for synchronous I/O with I/O in progress (a pipe being read) blocks; a worker that times out is abandoned, not terminated, and exits if its query ever returns.
- **Handle names** (`Handles.h`): `HandleNames::QueryName` names a handle of another process as a UI shows it, through a duplicate: processes and threads by ID and image name (the name from a callback, so the caller's snapshot can answer), tokens by user and logon session, files as DOS paths (`DosNames`, the device-to-drive table, built once by its owner), keys as `HKLM\`/`HKCU\`/`HKU\` (`RegistryName`), the rest through `ObjectNameQuery`. `CloseInProcess` closes a handle in its process (`DUPLICATE_CLOSE_SOURCE`) only if it still refers to an object of the given type, else fails with `ERROR_INVALID_HANDLE`.
- **Window stations** (`WindowStations.h`): `WindowStations::Enum`, every session's stations from the object namespace (`\Sessions\<n>\Windows\WindowStations`, the numbered directories; `\Windows\WindowStations` is session 0's again), and for the caller's session each station's visibility (`UOI_FLAGS`, `WSF_VISIBLE`) and desktops (`EnumDesktopsW`) with each desktop's heap (`UOI_HEAPSIZE`) and whether it's the input desktop (`OpenInputDesktop`), the desktops opened only on the caller's own station (`OpenDesktopW` looks in the process's station; Winlogon's only for SYSTEM). `EnumDesktopWindows` lists a desktop's top-level windows (own station only: another's would need `SetProcessWindowStation`, which a GUI process shouldn't call), each read by `ProcessWindows::Describe` (the `Enum`'s reading of one window, which sends no message).
- **Access masks** (`AccessMask.h`): `AccessMaskDecoder::Decode` names an access mask's rights for an object type ("QUERY_LIMITED_INFORMATION | SYNCHRONIZE", "ALL_ACCESS"), with unnamed bits as a hex remainder; `GetSpecificRights` (a type's one-bit rights) and `GetStandardRights` list them, for an ACL editor.
- **Object details** (`ObjectDetails.h`): `ObjectInspector::QueryHandle` inspects the object behind another process's handle through a duplicate with the handle's own access (which limits the queries), checked against the type it was listed with (a reused value fails with `ERROR_INVALID_HANDLE`): handle and reference counts, the type's statistics and generic mapping, the state particular to the type (event, mutant with its owner, semaphore, timer, I/O completion, section and image, file and named pipe, key, symbolic link, process, thread, token, job). `QueryTypeStatistics` gives any handle's type name and generic mapping. For a security editor: `OpenHandle` (the duplicate, kept by the caller), `GetSecurity` and `SetSecurity` (a self-relative descriptor, whole: reading needs `READ_CONTROL`, writing the DACL `WRITE_DAC` and the owner `WRITE_OWNER`). The counts are queried first, while the duplicate holds a full batch of precharged references: since Windows 8.1 a handle takes references 32,768 at a time and its uses consume them, so `References` is an estimate. `ownHandles` leaves the caller's other handles to the object out of the counts too (a handle it opened only to show the object, a security editor's duplicate). A file's queries run on a thread abandoned after a timeout, as a name query's can block.
