# Network, HTTP and ETW

Network interfaces, connections and tables, HTTP and VirusTotal, and the real-time ETW trackers and sessions. Read the entry before changing it.

- **Network** (`Network.h`): `NetworkInfo::GetInterfaces` (`GetIfTable2`) and `NetworkTracker`, which computes per-interface byte and packet rates between `Update()` calls over real elapsed time. `Network.h` deliberately uses no IP Helper types: consumers that include a full `windows.h` first can't include `winsock2.h` afterwards. `iphlpapi.lib` is linked by a `#pragma comment` in `Network.cpp`. `NetworkInterface::IsAdapter` keeps present interfaces with a physical medium, which drops filters, loopback, tunnels, WAN miniports and virtual switches (their counters duplicate a real adapter's).
- **ProcessNetwork** (`ProcessNetwork.h`): `ProcessNetworkTracker` counts TCP/UDP bytes sent and received per process from an ETW real-time session on Microsoft-Windows-Kernel-Network (events 10/11, 26/27, 42/43, 58/59; the payload starts with the PID and the size), read on its own thread. Enabling that provider needs elevation; Performance Log Users can start a session but get access denied enabling it. Sessions are named `<prefix> <pid>`, and `Start` stops ones whose process is gone. The events also give the connection (remote address and port first, then the local ones; ports in network order), so the bytes are counted per `ConnectionId` too: TCP by both ends, UDP by the local port (datagrams go to and come from anywhere); the closed ones are dropped every 30 seconds on the events' thread, against `ConnectionInfo::Read` (`IdOf` gives a connection's ID); `GetStartTime` says since when it counts.
- **IPC** (`Ipc.h`): `IpcTracker` reads one real-time session (system logger mode) with the system ALPC provider (`SystemAlpcProviderGuid`, whose events arrive as the classic ALPC class: send 33, receive 34, wait-for-reply 35, each with the message ID; the header has the process) and Microsoft-Windows-RPC (call start events 5 and 6: interface GUID, procedure number and protocol as UInt32, then the network address, endpoint and options as UTF-16 strings; "NULL" for no address). ALPC sends and receives are matched by message ID on the events' thread (pending messages dropped after 10 s), the client being the waiter for the reply, else the sender; RPC client calls are counted per client, interface, protocol, endpoint and address, and server calls map endpoints to their servers, looked up in `GetLinks`. `GetInterfaceName` knows a few documented RPC interfaces and reads HKCR\Interface otherwise. `EtwSession.h` (internal) has the session helpers it shares with `ProcessNetworkTracker` (properties, starting `<prefix> <pid>`, stopping orphaned sessions: only `<prefix><digits>` names, so a session whose name merely starts with the prefix, as another component's might, isn't taken for one).
- **File I/O** (`FileIo.h`): `FileIoTracker` counts reads and writes (bytes and operations) per process and file key from an ETW real-time session on Microsoft-Windows-Kernel-File (keywords FILENAME, CREATE, READ, WRITE: events 10 NameCreate, 12 Create, 15 Read, 16 Write), read on its own thread; elevation needed, sessions named and cleaned up as `ProcessNetworkTracker`'s (`EtwSession.h`). The process is the event header's (the issuer: System for lazy writes and paging I/O). Read and Write and Create have two layouts (version 0 has a pointer-sized ThreadId before FileObject; version 1 a UInt32 IssuingThreadId after FileKey). Names: NameCreate names a file key, Create a file object, which names its key at its first read or write; keys still unnamed go to a resolver thread of the tracker's own, which every 2 s looks their file objects up in the system handle table (`HandleEnumerator::EnumSystemHandles`, addresses only when elevated) and names them through a handle (`HandleNames::QueryName`), giving up on a key after 3 passes. Files idle for a minute are forgotten, unused names and file objects after two; names are converted to DOS paths in `GetFiles` (`DosNames`, rebuilt every 30 s).
- **Http** (`Http.h`): `Http::Get`, a synchronous HTTPS GET over WinHTTP (the system proxy, the caller's user agent, extra headers, one timeout for every phase), the status and body as received; nothing if the request couldn't be made (the last error set). `Http::Download` streams an `https://` URL into a file (redirects followed, as GitHub's release assets redirect to their storage), reporting to a `DownloadProgress` (a non-owning interface, not `std::function`), which can cancel; a status other than 200, a short read or a cancel fails and deletes the file. `winhttp.lib` by pragma.
- **VirusTotal** (`VirusTotal.h`): the public API v3 over WinHTTP, synchronous: `LookupHash` (GET `/api/v3/files/{sha256}`: `last_analysis_stats` and `last_analysis_date`, read with a few string searches rather than a JSON library; 404 is NotFound, 401/403 BadKey, 429 QuotaExceeded) and `UploadFile` (multipart POST to `/api/v3/files`, or for a file over 32 MB to the URL from `/files/upload_url`, up to 650 MB; the whole file in memory). The key goes in `x-apikey`; callers pace the requests (4 a minute on the free API). `FileHash::Sha256` (BCrypt, 1 MB reads). `winhttp.lib` and `bcrypt.lib` by pragmas.
- **ETW sessions** (`EtwSessions.h`): `Stop` (`ControlTraceW` by name, `EVENT_TRACE_CONTROL_STOP`, the properties with room for the names written back; `ERROR_MORE_DATA` counts as stopped) is its one change. `EtwSessions::Enum`, the sessions from `QueryAllTracesW` (a property block per session with room for the names; the logger ID is the low word of the handle in `Wnode.HistoricalContext`) and, from `EnumerateTraceGuidsEx` (`TraceGuidQueryList`, then `TraceGuidQueryInfo` per provider: its instances, each with its process and the `TRACE_ENABLE_INFO`s of the sessions that enabled it), each session's providers with level, keywords and processes, named from `TdhEnumerateProviders` (manifest and MOF providers; TraceLogging ones show only their GUIDs). The kernel's loggers take events by flags and list none; most sessions need elevation. `tdh.lib` by a pragma.
- **Network tables** (`NetworkTables.h`), read-only and plain text: `ReadNeighbors` (`GetIpNetTable2`, both families, interface aliases, the neighbor state, routers), `ReadRoutes` (`GetIpForwardTable2`, each interface's metric from `GetIpInterfaceEntry`, which Windows adds to the route's), `ReadDnsCache` (WMI's `MSFT_DNSClientCache` in `ROOT\StandardCimv2`, as `Get-DnsClientCache`; the caller initializes COM; dnsapi's undocumented `DnsGetCacheDataTable` returns nothing on current Windows, whose ipconfig uses `DnsGetCacheRecords`, also undocumented) and `FlushDnsCache` (`DnsFlushResolverCache`, which ipconfig imports, resolved at run time from System32's dnsapi.dll). `iphlpapi`, `ws2_32` and `wbemuuid` by pragmas.
- **Connections** (`Connections.h`): `ConnectionInfo::Read` lists TCP connections and UDP endpoints, IPv4 and IPv6, of all processes or one (`GetExtendedTcpTable`/`GetExtendedUdpTable`, no elevation), with their creation times and formatted addresses; `ConnectionKey` (protocol, addresses, ports, PID) identifies one across reads. `LookupName` is a reverse DNS lookup (`GetNameInfoW` with `NI_NAMEREQD`, Winsock started once for the process, `ws2_32` linked by a pragma), empty for an address without a name; it blocks, seconds for such an address, so callers run it on threads of their own. `IsUnspecified` tells 0.0.0.0 and `::`. `Close` resets a connection (`SetTcpEntry` with `MIB_TCP_STATE_DELETE_TCB`, elevation needed), which only IPv4 TCP connections with a remote end can be (`CanClose`; the IP helper has nothing for IPv6). Unlike `Network.h`, this header includes `winsock2.h`, so a consumer with a full `windows.h` must include `winsock2.h` before it.
- **Firewall** (`Firewall.h`): Windows Defender Firewall's rules and profiles through its COM API (`NetFwPolicy2`, `INetFwPolicy2`, `INetFwRule`/`INetFwRule3`; WRL `ComPtr`, `wil::unique_bstr`; COM must be initialized on the calling thread). `EnumRules` walks `INetFwRules`' `IEnumVARIANT` (780 rules in about 0.2 s) into `FirewallRule`s: names, descriptions and groups that are indirect strings ("@FirewallAPI.dll,-25000") are resolved with `SHLoadIndirectString`; a package's resource string whose package version is no longer installed (rules outlive the versions that added them; Get-NetFirewallRule shows the raw string) becomes the package's name. The raw name and group are kept: rule names aren't unique, so `SetEnabled` finds a rule again by `SameRule` (raw name and group, direction, action, protocol, ports, addresses, ICMP types, program and service without case, package, interface types and profiles; not the enabled state) and puts `Enabled` (elevation needed: E_ACCESSDENIED; `ERROR_NOT_FOUND` if it's gone). `GetPolicy` gives the active profiles and each profile's state, Block All Inbound and default actions. `ProtocolName` and `ProfilesText` word them. `Tests\FirewallTests.cpp` never changes the firewall: the rules are read and checked (inbound and outbound ones, Core Networking's group resolved, no group left unresolved, three profiles).
