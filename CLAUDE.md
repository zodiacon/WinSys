# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

WinSys is a C++20 library for low-level Windows development, extracted from the SystemExplorer project. It wraps native (NT) APIs for processes, threads, services, drivers, tokens/SIDs, LSA, kernel/process modules, and the Virtual Disk Service (VDS). Everything lives in the `WinSys` namespace.

## Build

Visual Studio / MSBuild solution (`WinSys.sln`). Primary target is `x64` (the solution maps ARM/ARM64 onto x64 configs). Toolset is v145 (VS 2026) with Windows SDK 10.0.26100.0 (see the phnt note below); the Win32 configs of the console projects still use v143.

```powershell
msbuild WinSys.sln /p:Configuration=Debug /p:Platform=x64
msbuild WinSys\WinSys.vcxproj /p:Configuration=Release /p:Platform=x64   # library only
```

Dependencies:
- **phnt** (native API headers): consumed via vcpkg (user-wide integration, no manifest in the repo). The local `phnt` copy was removed; the stale `.\phnt` entry in `AdditionalIncludeDirectories` is harmless.
  - Keep `WindowsTargetPlatformVersion` pinned to `10.0.26100.0`, not `10.0` (latest). SDK 10.0.28000 enlarged `XSTATE_CONFIGURATION` and reordered `KUSER_SHARED_DATA`, so phnt's `KUSER_SHARED_DATA` offset asserts in `ntexapi.h` fail (C2118 "negative subscript"). As of phnt 2025-02-05 (vcpkg) and upstream master 2026-03-26 this is unfixed.
  - The `pch.h` files wrap the phnt includes in `#define __ImageBase __ImageBase_phnt` / `#undef`, because phnt declares `__ImageBase` `const` and WIL doesn't (C2373 otherwise). Keep this wrapper in any new `pch.h` that includes both.
- **WIL** (`wil/resource.h`, `wil/com.h`): resolved from vcpkg. The console projects also reference NuGet `Microsoft.Windows.ImplementationLibrary` in `packages/` (`packages.config`); restore with `nuget restore WinSys.sln` if missing.
- `.gitmodules` lists a `WTLHelper` submodule, but it is not checked out or used by any project.

There is no unit-test framework. `WinSysCon` (process/thread enumeration + a `PerfTest` timing loop) and `VdsTest` (VDS enumeration) are console apps used for manual testing. Many APIs return more data when run elevated.

## Projects

- **WinSys**: static library, the core. Header-only pieces (notably `ProcessManager.h`) are included directly by consumers, which add `WinSys\` to their include path and link `ntdll`.
- **KWinSys**: WDM kernel driver (WDK toolset, `WindowsKernelModeDriver10.0`). Lets user mode open processes/threads/tokens/objects by address or name and duplicate handles when normal APIs are denied. `KWinSysPublic.h` holds the IOCTL codes and packed request structs shared with user mode; `WinSys/Driver.cpp` is the user-mode client that installs/loads the driver as the `KWinSys` service and issues the IOCTLs. Changes to the protocol must be made in both places.
- **WinSysCon**, **VdsTest**: test consoles referencing WinSys.

## Architecture notes

- **Native API usage**: `pch.h` defines `PHNT_MODE 1` / `PHNT_VERSION PHNT_THRESHOLD` and includes `phnt_windows.h` + `phnt.h` *instead of* `windows.h`. Don't include `windows.h` or `winternl.h` directly ahead of it. Exceptions are disabled (`_HAS_EXCEPTIONS 0`), so errors are reported through return values (`bool`, `nullptr`, `std::optional`, status codes), not throws. Don't use standard library parts that define exception classes (`std::format`, whose `format_error` derives from `runtime_error`; `std::function`, with `bad_function_call`; `<thread>`/`<mutex>`, with `system_error`...): without exceptions those classes have a different vtable (`_Doraise`), and an app built with exceptions that links WinSys gets `C4743` from LTCG in Release. Concatenate with `std::to_wstring` or use `StringCchPrintf`, and take callbacks as a non-owning reference (`ProcessNameLookup` in `Handles.h`).
- **ProcessManager<TProcessInfo, TThreadInfo>** (`ProcessManager.h`, header-only template): takes snapshots with `NtQuerySystemInformation` (`SystemFullProcessInformation` when elevated, else `SystemExtendedProcessInformation`). Callers can subclass `ProcessInfo`/`ThreadInfo` to attach extra data. Each `Update()` diffs against the previous snapshot by `ProcessOrThreadKey` (id + create time, see `Keys.h`) to produce new/terminated lists and CPU percentages.
  - `ProcessInfo::NativeInfo`/`ExtendedInfo` and `ThreadInfo`'s native pointers point **directly into the snapshot buffer**. The manager keeps two buffers (`m_Buffer[2]`, alternating `m_BufIndex`) so the previous snapshot's pointers stay valid for one update cycle. Preserve this double-buffering when changing the update logic, and don't cache these pointers across more than one `Update()`. To keep showing a terminated process, call `ProcessInfo::Detach` before the next `Update()`: it copies the entry (process, threads, extension, image name) into a buffer the object owns and repoints `NativeInfo`, `ExtendedInfo`, the package name and `ImageName`; its thread objects are dropped.
- **Handle-owning wrappers** (`Process`, `Thread`, `Token`, `Service`, `ServiceManager`, `Driver`) hold WIL RAII handles (`wil::unique_handle`, `wil::unique_schandle`, and so on) and are typically created through static factory methods like `OpenById`, not public constructors.
- **Network** (`Network.h`): `NetworkInfo::GetInterfaces` (`GetIfTable2`) and `NetworkTracker`, which computes per-interface byte and packet rates between `Update()` calls over real elapsed time. `Network.h` deliberately uses no IP Helper types: consumers that include a full `windows.h` first can't include `winsock2.h` afterwards. `iphlpapi.lib` is linked by a `#pragma comment` in `Network.cpp`. `NetworkInterface::IsAdapter` keeps present interfaces with a physical medium, which drops filters, loopback, tunnels, WAN miniports and virtual switches (their counters duplicate a real adapter's).
- **Network shares** (`NetworkShares.h`): `NetworkShares::Enum` tries `NetShareEnum` at levels 502 (path, uses, the share's security descriptor, read into `Permissions`: allow and deny ACEs with their trustees' names), 2 and 1 (name, type, comment), falling to the next on access denied (documented for non-administrators at 502 and 2; current Windows allows them locally), and says which it got; every share's `SHI1005_FLAGS_*` from `NetShareGetInfo` level 1005. `TypeName`, `RightsName` (the share permissions' Full Control, Change and Read masks) and `CachingName`. `netapi32.lib` by a pragma.
- **Page files** (`PageFiles.h`): `PageFiles::Enum` (`SystemInfo::GetPageFileInformationEx`, else the plain query without the minimum and maximum; sizes in bytes; `\??\` names as DOS paths) and `GetConfiguration` (the Memory Management key: `PagingFiles` lines, `<path> [<initial MB> <maximum MB>]`, `?:\pagefile.sys` meaning managed automatically and sizes of 0 a system-managed file, `ExistingPageFiles`, `ClearPageFileAtShutdown`, `DisablePagingExecutive`). No elevation needed.
- **Memory lists** (`MemoryLists.h`): `MemoryLists::Read` (`SystemMemoryListInformation`: zeroed, free, modified with its no-write and page-file parts, bad, the standby list per priority, in bytes, and the pages repurposed from each priority since boot, a count) and `Execute` (`NtSetSystemInformation` with a `SYSTEM_MEMORY_LIST_COMMAND`: empty working sets, flush the modified list, purge the standby list or its priority 0 part). Both enable SeProfileSingleProcessPrivilege, so they need elevation (`ERROR_PRIVILEGE_NOT_HELD` otherwise); `SystemInfo::GetMemoryListInformation` is the raw query.
- **Processor frequency** (`ProcessorFrequency.h`): `ProcessorFrequency` reads each logical processor's actual frequency as Task Manager's Speed, through PDH with the counters' English names (`PdhAddEnglishCounter`): `\Processor Information(*)\Processor Frequency` (rated) times `% Processor Performance` (over 100 while boosting; a rate, so `Open` collects once). Instances are `<group>,<number>`, mapped to indices group by group (`GetActiveProcessorCount`), as `SystemInfo`'s per-processor queries number them. `CallNtPowerInformation`'s `CurrentMhz` stays at the rated frequency, so it isn't used. `pdh.lib` by a pragma.
- **Disk** (`Disk.h`): `DiskInfo::GetVolumes` (fixed and removable drives with a letter; no media and `subst` drives skipped) and `DiskTracker`, which computes read/write rates, active time and response time between `Update()` calls. The counters come from `IOCTL_DISK_PERFORMANCE` on `\\.\X:`, opened with no access, so no elevation is needed. The handle is opened for each query, so removable drives can still be ejected. `winioctl.h` is already included through `vds.h` in the pch; including it again redefines its GUIDs (`INITGUID` is on).
- **ProcessNetwork** (`ProcessNetwork.h`): `ProcessNetworkTracker` counts TCP/UDP bytes sent and received per process from an ETW real-time session on Microsoft-Windows-Kernel-Network (events 10/11, 26/27, 42/43, 58/59; the payload starts with the PID and the size), read on its own thread. Enabling that provider needs elevation; Performance Log Users can start a session but get access denied enabling it. Sessions are named `<prefix> <pid>`, and `Start` stops ones whose process is gone. The events also give the connection (remote address and port first, then the local ones; ports in network order), so the bytes are counted per `ConnectionId` too: TCP by both ends, UDP by the local port (datagrams go to and come from anywhere); the closed ones are dropped every 30 seconds on the events' thread, against `ConnectionInfo::Read` (`IdOf` gives a connection's ID); `GetStartTime` says since when it counts.
- **IPC** (`Ipc.h`): `IpcTracker` reads one real-time session (system logger mode) with the system ALPC provider (`SystemAlpcProviderGuid`, whose events arrive as the classic ALPC class: send 33, receive 34, wait-for-reply 35, each with the message ID; the header has the process) and Microsoft-Windows-RPC (call start events 5 and 6: interface GUID, procedure number and protocol as UInt32, then the network address, endpoint and options as UTF-16 strings; "NULL" for no address). ALPC sends and receives are matched by message ID on the events' thread (pending messages dropped after 10 s), the client being the waiter for the reply, else the sender; RPC client calls are counted per client, interface, protocol, endpoint and address, and server calls map endpoints to their servers, looked up in `GetLinks`. `GetInterfaceName` knows a few documented RPC interfaces and reads HKCR\Interface otherwise. `EtwSession.h` (internal) has the session helpers it shares with `ProcessNetworkTracker` (properties, starting `<prefix> <pid>`, stopping orphaned sessions).
- **File I/O** (`FileIo.h`): `FileIoTracker` counts reads and writes (bytes and operations) per process and file key from an ETW real-time session on Microsoft-Windows-Kernel-File (keywords FILENAME, CREATE, READ, WRITE: events 10 NameCreate, 12 Create, 15 Read, 16 Write), read on its own thread; elevation needed, sessions named and cleaned up as `ProcessNetworkTracker`'s (`EtwSession.h`). The process is the event header's (the issuer: System for lazy writes and paging I/O). Read and Write and Create have two layouts (version 0 has a pointer-sized ThreadId before FileObject; version 1 a UInt32 IssuingThreadId after FileKey). Names: NameCreate names a file key, Create a file object, which names its key at its first read or write; keys still unnamed go to a resolver thread of the tracker's own, which every 2 s looks their file objects up in the system handle table (`HandleEnumerator::EnumSystemHandles`, addresses only when elevated) and names them through a handle (`HandleNames::QueryName`), giving up on a key after 3 passes. Files idle for a minute are forgotten, unused names and file objects after two; names are converted to DOS paths in `GetFiles` (`DosNames`, rebuilt every 30 s).
- **Zombies** (`Zombies.h`): `ZombieProcesses::Find` reads the system handle table, duplicates each Process handle from its owner (`PROCESS_DUP_HANDLE`; with query and synchronize access, else the handle's own) and keeps the exited ones (exit time from `GetProcessTimes`, else signaled), grouped by object address (elevated) or PID and creation time, with every handle holding each (its value, access and attributes); objects found running are skipped by address. This process's own handles are left out. The image name is the NT one (`ProcessImageFileName`, which an exited process keeps; `QueryFullProcessImageName` fails), as a DOS path.
- **Process windows** (`ProcessWindows.h`): `ProcessWindows::Enum` lists a process's top-level windows (Z order), then its message-only ones (`FindWindowEx(HWND_MESSAGE...)`), each followed depth-first by its child windows (`WindowInfo::Parent` is the parent's index); nothing sends a message (`InternalGetWindowText`), so a hung process can't hang the caller; other desktops aren't seen. `Show` (`ShowWindowAsync`), `BringToFront` (restore, then `SetForegroundWindow`, which the caller must be allowed) and `Close` (posts `WM_CLOSE`).
- **Firmware and TPM** (`Firmware.h`), read-only: `Firmware::GetType` (`GetFirmwareType`), `EnumVariables` (`NtEnumerateSystemEnvironmentValuesEx` with `SystemEnvironmentValueInformation`, enabling SeSystemEnvironmentPrivilege, which only an elevated token has; the buffer grows if variables are added between the calls) and `GetBootConfiguration` (from those variables: `BootOrder`, `BootCurrent`, `BootNext`, `Timeout`, `SecureBoot`, `SetupMode`, and each `Boot####` load option's attributes, description and the device path's file path nodes). `Tpm::GetInfo`: TBS's device info, and for TPM 2.0 one `TPM2_GetCapability` of the fixed properties (`TPM_PT_FAMILY_INDICATOR` on: family, level, revision, date, manufacturer, vendor strings, firmware version), big-endian, through a TBS context (`tbs.lib` by a pragma). Nothing is written to the firmware or the TPM.
- **Object namespace** (`ObjectNamespace.h`): `EnumDirectory` (`NtOpenDirectoryObject`, `NtQueryDirectoryObject` in 64 KB batches until `STATUS_NO_MORE_ENTRIES`), `GetSymbolicLink` (the target, growing the buffer when the link says so, and the creation time from `ObjectBasicInformation`), `Open` (a named object through its type's own open function: Directory, SymbolicLink, Event, Mutant, Semaphore, Section, Timer, IoCompletion, Job, Key, Session, EventPair; not devices or files, as opening a device can have effects; `ERROR_NOT_SUPPORTED` for other types), `GetHandleCount` (minus the handle opened to read it) and `Describe` (a handle of this process as the handle table lists it: access, attributes and type index from `NtQueryObject`, for `ObjectInspector`). Paths are case-insensitive (`OBJ_CASE_INSENSITIVE`).
- **VirusTotal** (`VirusTotal.h`): the public API v3 over WinHTTP, synchronous: `LookupHash` (GET `/api/v3/files/{sha256}`: `last_analysis_stats` and `last_analysis_date`, read with a few string searches rather than a JSON library; 404 is NotFound, 401/403 BadKey, 429 QuotaExceeded) and `UploadFile` (multipart POST to `/api/v3/files`, or for a file over 32 MB to the URL from `/files/upload_url`, up to 650 MB; the whole file in memory). The key goes in `x-apikey`; callers pace the requests (4 a minute on the free API). `FileHash::Sha256` (BCrypt, 1 MB reads). `winhttp.lib` and `bcrypt.lib` by pragmas.
- **Pool tags** (`PoolTags.h`): `PoolTagDescriptions` parses `pooltag.txt` (`<tag> - <binary> - <description>`; comments start with `//` or `rem`; the tag is the first four characters, spaces included, as the kernel pads short tags with spaces; the first line for a tag wins) from a file (`Load`) or text (`Parse`), and `FindFile` finds the Debugging Tools' copy under `%ProgramFiles(x86)%\Windows Kits\10\Debuggers\{x64,x86}\triage` (an environment variable rather than `FOLDERID_ProgramFilesX86`, which the library's `INITGUID` setup doesn't define). `TagText` shows a tag's four characters. The counters are `SystemInfo::GetPoolTagInformation`.
- **Sessions** (`Sessions.h`): `SessionManager::EnumSessions` (WTS, without listeners), `GetDetails` (logon/connect times, client name), `Disconnect`, `Logoff`. The detail queries raise first-chance RPC exceptions (0x6BA) that WTS handles, so pollers should enumerate without details and get them only on change. `wtsapi32.lib` is linked by a `#pragma comment` in `Sessions.cpp`.
- **ProcessModuleTracker** (`ProcessModuleTracker.h`): walks a process's address space (`VirtualQueryEx`, `GetMappedFileName`) for images and mapped data files, or uses ToolHelp when the process can't be opened with VM read. Each `EnumModules` rebuilds the list in address order, keeping the `ModuleInfo` objects of modules still there (key: mapped path + base) and reading the PE header only for new ones; `GetNewModules`/`GetUnloadedModules` are the differences from the previous call.
- **Handles** (`Handles.h`): `HandleEnumerator` lists a process's handles (or every process's, `EnumSystemHandles`) from the process (`ProcessHandleInformation`: cheap, no object addresses) or from the system handle table (`SystemExtendedHandleInformation`: object addresses when elevated, ~33 ms for ~360,000 handles; the buffer is kept). `ObjectTypes::GetName` (cached from `ObjectTypesInformation`); `ObjectTypes::Enum` (every type's counts, peaks, access mask, generic mapping, pool type and charges, read fresh: `ObjectTypeInfo`) and `PoolTypeName`. `ObjectNameQuery` queries object names on a worker thread with a timeout, because a name query on a file opened for synchronous I/O with I/O in progress (a pipe being read) blocks; a worker that times out is abandoned, not terminated, and exits if its query ever returns.
- **Token** (`Token.h`): the variable-size classes (groups, privileges, owner...) are queried into buffers of the size the token reports, as a domain account's token can have hundreds of groups. `ElevationType` isn't named `TokenElevationType` (or `TokenType`), which phnt/the SDK use for `TOKEN_INFORMATION_CLASS` values. `LsaSecurity::GetLogonSessionData` gets one logon session (only the caller's own unless elevated). `EnumLogonSessions` gets them all, leaving out those it can't read unless asked for them (`inaccessible`: then only the logon ID and `Error`, the Win32 error); `LogonTypeName` names a logon type. `EnablePrivilege` (by name or LUID; `TOKEN_ADJUST_PRIVILEGES`) and `SetIntegrityLevel` (`TOKEN_ADJUST_DEFAULT`; only lowering it needs no privilege, and lowering disables the enabled privileges) change a token.
- **Environment** (`Process::GetEnvironment`): reads the block from the process parameters, with its `EnvironmentSize`, from the 32-bit PEB for a WOW64 process (its code updates that one); names may start with `=` (the hidden per-drive current directories). Needs `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ`.
- **Process and thread operations** (`Processes.h`, `Thread.h`): besides the queries, `Process` sets the I/O priority (`SetIoPriority`; High enables `SeIncreaseBasePriorityPrivilege`), memory priority, affinity (`GetAffinity` fails with `ERROR_NOT_SUPPORTED` when the process spans processor groups) and efficiency mode (`SetEfficiencyMode`: EcoQoS plus the Idle class, as Task Manager; off restores Normal), reads its mitigation policies (`GetMitigations`, a `ProcessMitigations`), DPI awareness (`GetDpiAwareness`, from `GetDpiAwarenessContextForProcess`, telling Per-Monitor v2 and GDI scaling apart) and package full name (`GetPackageFullName`), reads the peak handle count (`GetPeakHandleCount`, `ProcessHandleCount`), reads and sets the critical flag (`IsCritical`, `SetCritical`: `ProcessBreakOnTermination`, setting it needs SeDebugPrivilege, which it enables), empties the working set (`EmptyWorkingSet`, `PROCESS_SET_QUOTA`) and restarts a process (`Restart`: image path, command line, current directory and environment read first, then terminated, waited for up to 5 s and created again with `CreateProcess` as the caller). `AttachDebugger` starts the AeDebug key's Debugger (`GetPostmortemDebugger`) with the PID for `%ld`, leaving out the crash-only `-e %ld` and `-j 0x%p`. Static helpers: `GetStructures` (the PEB, the 32-bit PEB of a WOW64 process, and each thread's TEB and stack bounds; a WOW64 thread's 32-bit TEB is two pages after its 64-bit one; stacks need `PROCESS_VM_READ`), `EnumLoadedModules` (PSAPI), `GetMainWindowTitles` (each process's frontmost visible, unowned, non-tool top-level window's title, `InternalGetWindowText`), `EnumProcessNames` (ToolHelp, which needs no access to the processes) and `GetHungProcesses` (the processes with a visible, hung top-level window, `IsHungAppWindow`, as Task Manager's "Not responding"; DWM's `Ghost` windows, which stand in for hung ones and report hung themselves, are left out). `Process::Run` (a command line through ShellExecuteEx, optionally with the `runas` verb) and `Process::RunAs` (CreateProcessWithLogonW: another user's process, with the profile loaded or the credentials for network access only) start processes; `Process::RunLimited` starts one with a Safer normal-user token made from the caller's (Administrators deny-only, most privileges removed), lowered to medium integrity (`CreateProcessAsUser`, which accepts such a filtered token of the caller's own without a privilege). On a system with more than one processor group (over 64 logical processors; `SystemInfo::GetProcessorGroups`), a process spanning groups (every process, by default, since Windows 11) is restricted by its default CPU sets (`GetDefaultCpuSetMasks`/`SetDefaultCpuSetMasks`, `GROUP_AFFINITY` per group, looked up at run time as they're Windows 11 and Server 2022 on) rather than a mask; `GetGroups` lists the groups its threads are in. `Thread` has `GetStartAddress` (`ThreadQuerySetWin32StartAddress`, `THREAD_QUERY_INFORMATION`; the process snapshots zero their start addresses for a caller that isn't elevated), `Suspend`, `Resume`, `Terminate`, `SetPriority`, `SetGroupAffinity` (which moves a thread to another group), `GetAffinity`/`SetAffinity` (within the thread's processor group; `GetAffinity` also gives the processors it may be given: its process's affinity when that's in the group, else the group's active ones) and `GetCreateTime` (to tell a thread from a later one with the same ID). `ThreadAccessMask` and `ProcessAccessMask` have the flag operators.
- **Handle names** (`Handles.h`): `HandleNames::QueryName` names a handle of another process as a UI shows it, through a duplicate: processes and threads by ID and image name (the name from a callback, so the caller's snapshot can answer), tokens by user and logon session, files as DOS paths (`DosNames`, the device-to-drive table, built once by its owner), keys as `HKLM\`/`HKCU\`/`HKU\` (`RegistryName`), the rest through `ObjectNameQuery`. `CloseInProcess` closes a handle in its process (`DUPLICATE_CLOSE_SOURCE`) only if it still refers to an object of the given type, else fails with `ERROR_INVALID_HANDLE`.
- **GPU** (`Gpu.h`): D3DKMT. `GpuInfo::GetAdapters` (`D3DKMTEnumAdapters2`; software and non-rendering adapters left out; names from DXGI; engines from `KMTQAITYPE_NODEMETADATA`, grouped by name; aperture segments count as shared memory). `GpuTracker` samples the nodes' running times (treated as 100 ns units) and the segments' resident bytes; an engine's utilization is its busiest node's, an adapter's its busiest engine's. NPUs are a second adapter list (`GpuAdapterKind::Npu`, for `GetAdapters`, `GpuTracker` and `QueryProcess`): the compute-only adapters DXCore marks with `DXCORE_HARDWARE_TYPE_ATTRIBUTE_NPU` (dxcore.dll loaded at run time; the GUID copied rather than linked), named by DXCore's driver description; the GPU list leaves them out. `GpuInfo::QueryProcess` gives a process's usage between calls (`GpuProcessState` holds the previous values); it needs `PROCESS_QUERY_INFORMATION` (a limited handle fails with `STATUS_INVALID_PARAMETER`). `dxgi.lib` and `gdi32.lib` are linked by `#pragma comment`.
- **Connections** (`Connections.h`): `ConnectionInfo::Read` lists TCP connections and UDP endpoints, IPv4 and IPv6, of all processes or one (`GetExtendedTcpTable`/`GetExtendedUdpTable`, no elevation), with their creation times and formatted addresses; `ConnectionKey` (protocol, addresses, ports, PID) identifies one across reads. `LookupName` is a reverse DNS lookup (`GetNameInfoW` with `NI_NAMEREQD`, Winsock started once for the process, `ws2_32` linked by a pragma), empty for an address without a name; it blocks, seconds for such an address, so callers run it on threads of their own. `IsUnspecified` tells 0.0.0.0 and `::`. `Close` resets a connection (`SetTcpEntry` with `MIB_TCP_STATE_DELETE_TCB`, elevation needed), which only IPv4 TCP connections with a remote end can be (`CanClose`; the IP helper has nothing for IPv6). Unlike `Network.h`, this header includes `winsock2.h`, so a consumer with a full `windows.h` must include `winsock2.h` before it.
- **.NET** (`DotNet.h`): `DotNetInfo::GetCoreRuntimeProcesses` (the `dotnet-diagnostic-<pid>` pipes of .NET Core and later) and `HasFrameworkRuntime` (the CLR's `Cor_Private_IPCBlock[_v4]_<pid>` section in the process's session; access denied counts as present).
- **Symbols** (`SymbolHandler.h`): DbgHelp isn't thread-safe, so the caller must make every call (handlers and `MiniDump`) from one thread. `SetOptions` once; `ForProcess` (by ID and creation time, so a reused ID fails) and `ForKernel` (the loaded drivers from `SystemModuleInformation`; their bases need elevation; a fixed pseudo-handle, so one at a time). `GetSymbol` refreshes the module list (at most every 2 s) when an address is in none. `CaptureStack` suspends the thread only to copy its context and stack (from the stack pointer to `StackBase`, at most 1 MB; a WOW64 thread's 32-bit ones too) and walks the copy, so no symbol download happens with the thread suspended. `GetModuleSymbols` tells where a module's symbols came from (PDB with its path, exports only, none, or not loaded yet: with deferred loads, only `GetSymbol` loads them). `MiniDump::Write` writes a mini or full dump. Which `dbghelp.dll` is used is the caller's choice (load it first; the system's can't download symbols).
- **Kernel modules** (`KernelModules.h`): `KernelModules::Enum` (built on `SystemInfo::GetKernelModuleInformation`) gives the kernel's loaded modules with Win32 paths (`ToWin32Path`: `\SystemRoot\`, `\??\`, `\Device\...` and rootless `\Windows\...` paths) and wide names (the kernel's are ANSI); the bases are zero unless elevated. With `SystemModuleInformationEx` (`GetKernelModuleInformationEx`) each module also has its image's link time, checksum and preferred base; if that query fails, the plain one is used without them. `SymbolHandler::ForKernel` uses it. `DriverImagePath` gives a driver service's image (its ImagePath, possibly relative to the system root, or the default `System32\drivers\<name>.sys`) as such a Win32 path, to match a service with its loaded module.
- **Files** (`FileSignature.h`, `FileVersion.h`): `FileSignature::Verify` (Authenticode: the embedded signature, else the system catalog that lists the file's hash; no revocation checks, so nothing goes to the network; safe on any thread, but the catalog lookups may use COM) and `FileVersion::Read` (the version resource's description, company and version, in its first listed language).
- **Access masks** (`AccessMask.h`): `AccessMaskDecoder::Decode` names an access mask's rights for an object type ("QUERY_LIMITED_INFORMATION | SYNCHRONIZE", "ALL_ACCESS"), with unnamed bits as a hex remainder; `GetSpecificRights` (a type's one-bit rights) and `GetStandardRights` list them, for an ACL editor.
- **Jobs** (`Job.h`): no API opens a process's job, so `JobInfo::FindProcessJobs` scans the system handle table for Job handles, duplicates them from their owners (`PROCESS_DUP_HANDLE`, so mostly only when elevated), keeps those `IsProcessInJob` accepts (told apart with `NtCompareObjects`) and orders them innermost first by active processes (nothing documented gives a job's parent; `ordered` says whether the counts told them apart). Also a job's name, active processes and process IDs.
- **Wait chains** (`WaitChain.h`): `WaitChainTraversal::GetThreadWaitChain` (WCT, synchronous, with ole32's COM callbacks registered once). WCT's thread `WaitTime` is the clock tick the wait began on, not a duration; it's converted to the milliseconds since.
- **Object details** (`ObjectDetails.h`): `ObjectInspector::QueryHandle` inspects the object behind another process's handle through a duplicate with the handle's own access (which limits the queries), checked against the type it was listed with (a reused value fails with `ERROR_INVALID_HANDLE`): handle and reference counts, the type's statistics and generic mapping, the state particular to the type (event, mutant with its owner, semaphore, timer, I/O completion, section and image, file and named pipe, key, symbolic link, process, thread, token, job). `QueryTypeStatistics` gives any handle's type name and generic mapping. For a security editor: `OpenHandle` (the duplicate, kept by the caller), `GetSecurity` and `SetSecurity` (a self-relative descriptor, whole: reading needs `READ_CONTROL`, writing the DACL `WRITE_DAC` and the owner `WRITE_OWNER`). The counts are queried first, while the duplicate holds a full batch of precharged references: since Windows 8.1 a handle takes references 32,768 at a time and its uses consume them, so `References` is an estimate. A file's queries run on a thread abandoned after a timeout, as a name query's can block.
- **Service configuration** (`Service.h`): `ChangeConfig` (a `ServiceConfigChange` of optional start type, error control, binary path, display name, account and password: `ChangeServiceConfig`), `SetDescription`, `SetDelayedAutoStart`, `GetFailureActions` and `SetFailureActions` (`ServiceFailureActions`: reset period, reboot message, command, the actions with their delays, and `OnNonCrashFailures`, the failure actions flag). They need `SERVICE_CHANGE_CONFIG`; a Restart action also needs `SERVICE_START` on the handle, and a Reboot action SeShutdownPrivilege, which `SetFailureActions` enables for the call. `TokenAccessMask` has the flag operators. `GetDependents` (`EnumDependentServices`, `SERVICE_ENUMERATE_DEPENDENTS`) lists every service depending on one, directly or not; the active ones come in the order to stop them. `GetSecurity`/`SetSecurity` read and write the service's security descriptor (`QueryServiceObjectSecurity`, `SetServiceObjectSecurity`; `READ_CONTROL`, `WRITE_DAC`, `WRITE_OWNER`, which `ServiceAccessMask` has), and `GetGenericMapping` gives the SCM's generic mapping; `AccessMaskDecoder` knows a "Service" type for its rights. `GetTriggerDetails` copies the triggers out with their subtypes and data items (`GetTriggers` gives only the types, actions and data item counts, its pointers null, as the buffer they would point into is freed), and `GetEventProviderName` names an ETW provider from its `WINEVT\Publishers` key. `ServiceManager::Install` builds the dependencies' list from `;`-separated names of any length and keeps `CreateService`'s error for the caller (closing the SCM handle may change it).
- **Process memory** (`ProcessMemory.h`): `Find` (a byte pattern in an address range, through the committed regions that can be read without side effects, in 1 MB chunks that overlap by the pattern's length; adjacent readable regions searched as one range, so a match may cross them; optionally ignoring ASCII case, with `wide` by UTF-16 units, folding only units whose high byte is zero), `Read` (what can be read; unreadable pages as zeros, page by page when the whole read fails), `GetMappedFileName` (the file mapped at an address, from `NtQueryVirtualMemory`'s `MemoryMappedFilenameInformation` with a buffer that grows, as psapi's `GetMappedFileName` cuts a name to the buffer it's given; `ProcessModuleTracker` uses it too), `Write` (`WriteProcessMemory`, which makes a read-only or executable page writable for the write when the handle has `PROCESS_VM_OPERATION`) and `MaxAddress`. `Find` avoids `<functional>`'s searchers (see the exception note above).
- **Other**: `Sid::AppContainerMoniker` (`AppContainerLookupMoniker`, in kernelbase but no SDK header, resolved at run time); `ServiceManager::GetServiceDll` (the `ServiceDll` value of a service's key or its `Parameters` subkey; a user service instance's from its template's key).
- **VDS** (`VirtualDiskService`, `VdsProvider`, `VdsVolume`) is COM-based and uses `wil::com_ptr`. The caller must initialize COM.

## Conventions

- Tabs for indentation, `m_` prefix for members, `s_` for statics, PascalCase methods, `[[nodiscard]]` on getters.
- Holders of static functions are plain `struct X final { static ... };`, without MSVC's non-standard `abstract` keyword.
- Every `.cpp` in a project starts with `#include "pch.h"`.
- When adding a source file, register it in both the `.vcxproj` and the `.vcxproj.filters`.
